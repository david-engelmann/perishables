# Build round 23. Orphan coverage beyond measures, built and rejected in parts

Date. 2026-11-25. Stacked on the coverage branch. The last item from the self review's accepted list, closed here with part of it built and part of it rejected on the record.

What is information, stated precisely. A model that carries fields and is reached by no relationship is a dead end in the graph, the entity half of the design record's orphan class. It is built, as a note and never a finding, under two gates. The definition must carry more than one model and at least one relationship, because reachability is a claim only a multi model document with declared joins makes at all. A file based manifest with no joins, a single model export, a single table space, none of these claims a graph, so none of them earns the note. And the model must carry measures or dimensions of its own, because an entry point with no fields, a Cube view above all, is a door into the graph rather than a room nothing reaches. The gate is a new Cube fixture, an audit log cube carrying a field and joining to nothing in a document that does declare joins, earning exactly the one note, while every existing fixture's note count in the programme is unchanged, each verified against the gating by hand.

What is rejected, with reasons, no longer carried as accepted. Orphan metrics are rejected. A metric is the endpoint a semantic layer exists to serve, and nothing referencing it is its normal state in every ecosystem in the programme. The one apparent exception proves the rule, a dbt derived metric references its ingredients, and there the unreferenced simple metrics beside it are still endpoints. A note on every endpoint is noise on every real definition. Orphan dimensions are rejected. A dimension is a leaf field, and the references that would make it used, measure SQL in LookML and hierarchy levels in AtScale, are already graded in the other direction by the dangling family. A dimension no measure uses is a filter field by design. Extending the existing orphan measure note beyond name linked ecosystems is rejected. In expression based ecosystems the measures are directly queryable endpoints, and the note's information content exists only where metrics name the measures they read, which is the dbt shape the note already covers.
