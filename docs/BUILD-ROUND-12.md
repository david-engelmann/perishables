# Build round 12. Cross ecosystem slice 6, the Looker reader

Date. 2026-11-24. The sixth build from the cross ecosystem design record, stacked on slices 1 to 5.

What landed. A Looker reader in the adapter crate over the JSON reader. LookML is a custom language and parsing it is a project of its own, so the reader takes the JSON the Looker API returns for a model's views and explores, assembled into one document, the shape the research names as offline gradeable beside the LookML files. A native LookML reader is a later surface and is stated as this slice's boundary.

The mapping. Views are the models. Dimensions and measures carry labels and descriptions as before, and Looker's structured synonyms list becomes alias claims, graded by the collision family with the same treatment Ossie synonyms get. Explores declare joins to other views, and those are relationships, graded for dangling targets by the structural family. No new check code was needed. Both families the slice exercises already existed, which is the design record's thesis again.

The gate. A clean model grades clean, its two synonym claims colliding with nothing. A defect model produces exactly two findings, a dangling explore join to a view the model does not carry, and a name collision where a dimension's synonym claims the word a measure already answers to as its label.

Landing route. Stacked on cross-ecosystem-cube-1 as branch cross-ecosystem-looker-1, for the standing route. AtScale follows in the same pass, per the sweep's charge.
