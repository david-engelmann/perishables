Date. 2026-11-25. The eleventh cross ecosystem build, stacked on the LookML slice 1 branch, implementing slice 2 of the design record at docs/DESIGN-LOOKML.md.

What landed. A project reader beside the single file reader. Files merge into one model, so views and explores living in different files grade together. Three surfaces arrive with scope. Dotted cross view references in measure SQL, excluded in slice 1, are now carried whole and resolve against a qualified field set the project reader builds, view dot field for every field in the project. Extends is treated as what it is, a declared structural reference between views, so it enters as a relationship and a missing parent grades as a dangling finding through the existing family, while inheritance merges the parent's fields into the child over as many passes as the chain needs. Include patterns from model files match against the provided file paths with a minimal star matcher, and a pattern matching nothing is a coverage note rather than a finding, because a partial file set cannot prove a file absent. The command line grades several LookML files as one project.

One modeling decision is recorded rather than buried. An inherited field keeps its home view as its model in the grading model. It is the parent's field made addressable through the child, which the qualified field set records, and not a second competing claim by the child. Without that, inheritance would manufacture name collisions between a view and its own parent on every shared field name, which is a false positive by construction.

The gate is a small real project on disk, four files, graded whole and graded with a file removed. With the customers file removed, the cross view reference and the explore join both dangle, which is what project scope means when it is absent.
