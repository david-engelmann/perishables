# Design record. Cross ecosystem grading

Status. Design record only, written 2026-11-23 under the roadmap charge from the applicability audit vendor layer addendum. No build is charged by this record. Main reviews it before any adapter is ordered.

Evidence base. The vendor semantic layer research report of 2026-11-23, read firsthand, primary vendor sources where it marks them, and the audit addendum of the same date. Three corrections from that research are carried into every section below and are not negotiable in later work. The field named ai_context belongs to Apache Ossie and to Cube, not to dbt, whose native surface is description, label, and meta. The Snowflake figures of 1MB and 32K tokens are legacy semantic model numbers and are superseded for semantic views, where current guidance is a roughly 100K token guideline with pruning risk and no hard limit. The Palantir signal named UnreferencedRuleSets is unconfirmed, with no trace in documentation or search, and nothing in this record is designed on it.

## The claim

Perishables grades trust claims wherever they are recorded. The vendor semantic layers record the same claims in vendor dress. A Snowflake verified query whose verified_at predates the last change to its view is a lapsed verification. A stored question and SQL pair is an attested computation whose claim can be recomputed. A metric that references a measure that no longer exists is a dangling target. A synonym that names two different metrics is two live claims to one name. The ecosystems differ in format and in access. The defects rhyme, and the rule families that grade them already exist in this repo.

The architecture follows from that. Each ecosystem gets a reader, an adapter that parses the vendor definition into one normalized grading model of entities, fields, relationships, verification events, and ground truth sets. The existing rule families run over the normalized model and know nothing about vendor formats. Readers live in adapter crates, as execution does today, and the library stays free of format knowledge and of IO beyond the bundle it is handed. The four locked calls are OKF shaped and do not change. Cross ecosystem grading is a new surface beside them, under the same versioning discipline, and the upkeep seat is told before it ships, not after.

## The four dimensions, mapped

Discoverability and semantic collisions. In OKF this is the provenance family, stated facts checked for completeness and coherence. In vendor dress the stated facts are descriptions, labels, and synonyms. Coverage grading asks which entities, fields, and metrics carry a description, which carry a label, and where synonyms exist, which fields carry them. Collision grading is the coherence half, and it is new in shape but not in kind. Two definitions answering to the same label or synonym is the semantic layer form of two live claims to one identity, and it grades the way supersession integrity grades, as a defect in the record, independent of which definition is right. Perishables does not judge which metric deserves the name. It reports that the name is claimed twice.

Grounding and verification currency. This is the currency family, the heart of the tool, and it transfers almost without translation. Where a platform stores a verification event with a timestamp, the event is current when it stands at or after the last change to the thing it verifies, and lapsed when it predates that change, exactly the rule SPEC 5.3 states for OKF. Two cautions are part of the mapping. Snowflake verified_by is a free text name, not an actor scheme, so it earns no tier derivation of the kind OKF gives human and team actors. It grades as coverage, whether the field is populated, and as age, never as identity. And where a platform stores no verification construct at all, which is dbt's position, absence grades as information in the posture this repo already uses for a concept with no sources, reported and never gated.

Behavioral ground truth evals. This is the re execution family. A stored question with its expected SQL is a claim that the platform, asked this question, produces this result, and running the question through the platform's own API and comparing result sets is re execution with a warehouse where the sandbox was. The verdict vocabulary carries over, agreement, disagreement, and the honest family of could not run, with one addition the OKF profile never needed. Only two platforms store ground truth in the definition, Snowflake and Databricks. Everywhere else the questions are grader authored, and a grader authored question is a different epistemic class from a stored one, because the platform never claimed it. Pass rates from the two classes are never mixed in one number, and reports name the class beside the rate.

Structural integrity. This is the chain walk generalized from lines to graphs. Dangling references, a metric built on a missing measure, a relationship pointing at a missing table, are the dangling superseded_by of this world. Orphans, entities and metrics nothing references and no path reaches, are dead ends in the graph. Multi path joins, where two routes connect the same tables with different grains, are the fan trap the Snowflake cookbook names as its top wrong answer cause, and they grade as ambiguity defects in the definition, whether or not any query has hit them yet. One fidelity rule from the research binds everything in this dimension. Ossie converters report constructs they cannot carry, and a conversion that reports loss is a stated fact to grade. No round trip is ever graded as faithful without consuming the converter warning stream, because a construct preserved only inside a custom extension is invisible to native tools on the far side.

Drift. No vendor in the set stores a stamp comparing a definition against the live schema, so definition versus live schema drift is grader computed on every platform, as it is in OKF. The split the audit addendum names stands. This tool computes drift where a build is charged. The upkeep engine schedules and reports it. That half is anchorwatch's roadmap item, not this record's.

## The ecosystems, in gradeability order

First, dbt and Apache Ossie. The definitions are files. dbt parse writes semantic_manifest.json, manifest.json carries semantic models and metrics, and the source YAML lives in git, so the whole surface is offline, deterministic, and diffable, which is the profile this tool is built for. The gradeable facts are descriptions, labels, and meta dictionaries, the entity graph across semantic models, metric dependency through type_params, and freshness from git provenance and the source freshness artifacts. Ossie documents add ai_context at model, dataset, and field level, carrying instructions, synonyms, and examples, which is where synonym coverage and grader relevant context live in this ecosystem. The honest limits are stated plainly. There is no native verification event and no stored ground truth, so the currency family grades provenance and freshness only, and behavioral evals on this surface are grader authored by necessity.

Second, Snowflake semantic views. The definition exports to YAML through SYSTEM$READ_YAML_FROM_SEMANTIC_VIEW, with GET_DDL as the second read path, and the exported YAML grades offline once extracted, though extraction needs an account and a role with privileges on the view. This is the richest currency surface outside OKF. Verified queries carry verified_by and verified_at, relationships are declared in the open, sample values and enum flags ground dimensions in stated data, and custom instructions include a question categorization surface that grades as a stated refusal policy. Behavioral evals run through the Cortex Analyst REST API against the stored verified queries. Design limits follow current guidance, the roughly 100K token guideline with a pruning warning, and never the superseded legacy figures. Approval and owner status are announced as living in Horizon Business Ontology rather than in the YAML, in preview with no public read API, so that signal is out of grading reach today and this record does not pretend otherwise.

Third, Databricks Genie spaces. The ground truth is real, benchmarks.questions pairs questions with expected SQL inside the serialized space, and example question SQLs add a second trusted set, with certification as a governed tag on Unity Catalog objects and metric view synonyms under the 1.1 YAML. Behavioral evals run through the Conversation API. It ranks last for a local first tool for one reason, access. Reading the serialized space requires the API with at least edit permission on the space, and behavioral runs need a warehouse. An exported space file grades offline exactly as a Snowflake export does, and a build would accept exports from day one, but the native read path is a permissioned API call, and that ordering fact is the ranking.

## What stays out

Learned layers stay out, entirely. Genie Ontology mines snippets from dashboards and queries and ranks context with OntoRank, and neither the snippets nor the scores are exportable through any documented API. A grader may approximate authority from readable inputs such as certification, recency, and usage, and must label the result an approximation, never the vendor's score. Anything else is fabrication with a chart.

UI only health signals stay out. Palantir Foundry is the richest ontology in the set and the least gradeable from outside. Its health and cleanup signals live in Ontology Manager with no public API, its definitions have no stable offline form, and everything is scoped to an enrollment and an application. The one named hook the outside summary offered for it could not be confirmed anywhere and is treated as misnamed or internal. Foundry grading waits for a surface that exists.

Fabric IQ stays out for now. Its ontology is TMDL, readable through getDefinition, and its bindings are a genuinely good drift substrate, but the experience is in preview with a retirement date on the old one, and it stores no ground truth and no verification fields. It is a watch item, named here so the omission is a decision and not an oversight. Cube, Looker, and AtScale sit between Databricks and Fabric in the research ranking, all git native or API readable with real description surfaces, and Cube carries a true ai_context of its own. If the programme extends past the charged three, Cube is fourth.

## Discipline for any build that follows

Every adapter ships the way the OKF auditor did, cheapest failure first, with planted defect fixtures in the native format and labels naming the expected rule, and a gate that fails when a must fail fixture passes. A dbt manifest with a dangling metric reference and a synonym collision is the obvious first pair. No adapter grades a surface it cannot read deterministically, no pass rate mixes stored and grader authored questions, and no learned layer is approximated without the label. Open questions for Main are the predicate and report story for cross ecosystem verdicts, whether they join the attestation note's in-toto mapping as a second predicate family, and the order of the second and third adapters if the first proves the model.
